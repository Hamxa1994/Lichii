# Changes of 9 November 2026

Everything here was written and built on a Windows PC with an AMD RX 580 2048SP (Polaris, no
float16, `amdvlk64.dll`). Only the first item has been confirmed in a real game; the rest is built
but untested, and is marked so.

## Memory

| Change | Where | Status |
|---|---|---|
| Guest memory is reserved and committed in 2 MiB chunks on demand. The Switch 2 layout needs a 14 GiB backing, and committing it at boot used up Windows' commit limit, after which the driver refused every allocation (out of memory with 1 GB of VRAM in use). `EDEN_NX2_LAZY_COMMIT=0` restores the eager commit. One log line per GiB committed. | `common/host_memory.cpp` | Confirmed: the game boots and runs. |
| Texture cache eviction cap 5 GiB to 8 GiB, so the device budget decides. | `texture_cache/texture_cache_base.h` | Confirmed in the log. |
| Device-memory reserve `min(1/8, 1 GiB)` to `min(1/8, 768 MiB)`. | `vulkan_common/vulkan_device.cpp` | Built. |

## Frame generation (FSR3 type, runs on any Vulkan GPU)

| Change | Where | Status |
|---|---|---|
| The interpolation used the same frame twice (history and current were both overwritten before it ran). It now keeps the previous and the latest frame. | `present/fsr3_frame_gen.cpp` | Built. |
| Warp direction, flow units and the "3x3 median" (it sampled with the wrong texel size) corrected. | `fsr3_frame_interpolation.comp` | Built. |
| Three-level luma pyramid with a coarse-to-fine optical flow. Reach about 60 full-size pixels, about 18 candidates per pixel at full size. The previous frame's pyramid is kept. Each vector carries its matching cost, and unreliable pixels show the nearer real frame instead of a blend. | `fsr3_optical_flow.comp`, `fsr3_luma_pyramid.comp` | Built. |
| Median filter of the flow once per real frame (`fsr3_flow_median.comp`), so each generated frame reads one filtered texel instead of sorting nine vectors per pixel. | `present/fsr3_frame_gen.cpp` | Built. |
| Crash fix: the interpolation no longer rewrites a descriptor set for every generated frame (the worker thread could still be executing earlier commands that use it, which crashed `amdvlk64.dll`). Every descriptor is written once at construction; the result is rendered into an internal image and copied to the presented frame. | `present/fsr3_frame_gen.cpp` | Built; the crash has not been reproduced here, so this is the best-supported cause. |
| Original and generated frames per second: a log line once a second and a status-bar entry. | `common/frame_gen_stats.h`, `renderer_vulkan.cpp`, `yuzu/main_window.cpp` | Built. |

## Rendering

| Change | Where | Status |
|---|---|---|
| Passthrough geometry-shader pipelines were skipped on GCN4 and older AMD GPUs (the driver crashes building any geometry stage), so their draws never appeared. When the shader does not write a layer or viewport index, the stage is left out and the vertices go straight to the fragment shader. | `renderer_vulkan/vk_pipeline_cache.cpp` | Built. |
| "Dropping GPU-modified image" is a rate-limited warning, not an assert on every join. | `texture_cache/texture_cache.h` | Built. |
| **Crash fix (both stage-load crashes):** a pipeline that was never built (the GCN4 geometry case) had its pipeline bind skipped, but its draw was still recorded, so the worker thread called `vkCmdDrawIndexed` with no pipeline bound and the AMD driver crashed (`amdvlk64.dll`, both dumps, both logs end with a skipped-geometry-pipeline warning). The scheduler now remembers that the bound pipeline is missing and every draw command (direct, mesh, indirect) drops itself. Port of Eglantine PR #720. | `vk_scheduler.h`, `vk_graphics_pipeline.cpp`, `vk_rasterizer.cpp` | Built; found from the dump and logs, not yet confirmed in a game. |
| A draw using a pipeline that was never built (the GCN4 geometry case, or a build that failed) is dropped before its setup, not after. `Configure` did all the buffer, texture and render-target work for the draw and only then noticed the pipeline was missing; in the profiled scene that is 27% of the game's draws (about 380 of 1,400 a frame). | `vk_graphics_pipeline.h`, `vk_rasterizer.cpp` | Built; found by the sampling profiler and the draw counters, gain not yet measured. |
| `EDEN_NX2_GCN4_GEOMETRY=1` builds geometry pipelines on GCN4 anyway, to test whether a newer driver survives them (those draws, layered shadow passes, are skipped otherwise). | `vulkan_device.h/.cpp` | Built. |

## Not done

- A Direct3D 12 renderer. The renderer is Vulkan throughout the video core (about 150 files);
  a second backend is a project of its own, not an option.
- LSFG quality mode: needs a genuine `Lossless.dll` and a float16 GPU.
- GPU timestamps for the frame generation passes. `run_lichii_profile.bat` starts the emulator with
  `EDEN_NX2_GPU_PROFILE` and `EDEN_DKB_FRAME_TRACE` on, which measure where a slow stretch goes.
- Missing or slow textures beyond the passthrough geometry fix: see the log for the specific
  causes, they are not one bug.
